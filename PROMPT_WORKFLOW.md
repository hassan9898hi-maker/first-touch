## 1. نظرة عامة على التطبيق (App Overview)

**FIRST TOUCH** هو منصة متكاملة لإدارة مشاريع البناء والتشييد، تربط بين أربعة أطراف رئيسية:
- **مالك المشروع (Owner)** - صاحب المشروع الذي يريد البناء
- **المقاول (Contractor)** - الذي ينفذ أعمال البناء
- **المفتش (Inspector)** - الذي يراقب جودة العمل
- **المطور العقاري (Developer)** - شركة تطوير عقاري تدير مجمعات سكنية/تجارية متعددة الوحدات

### التقنيات المستخدمة:
- **Frontend**: React 19 + Vite
- **Backend**: Node.js + Express + Prisma
- **Database**: SQLite (تطوير) / PostgreSQL (إنتاج)
- **Real-time**: Socket.io
- **Auth**: JWT + Refresh Tokens

## 2. سير عمل التسجيل والمصادقة (Authentication Workflow)

### 2.1 التسجيل (Registration)
```
المستخدم → صفحة التسجيل → إدخال البيانات → إنشاء الحساب → تأكيد البريد الإلكتروني
```

**الخطوات التفصيلية:**
1. المستخدم يفتح التطبيق ويختار "إنشاء حساب جديد"
2. يدخل البيانات المطلوبة:
   - الاسم الكامل (عربي + إنجليزي)
   - البريد الإلكتروني
   - رقم الهاتف
   - كلمة المرور
   - الدور: مالك / مقاول / مفتش / مطور عقاري
3. النظام يتحقق من صحة البيانات (Zod Validation)
4. تشفير كلمة المرور (bcrypt - 12 rounds)
5. إنشاء الحساب في قاعدة البيانات
6. إرسال رابط تأكيد البريد الإلكتروني (إذا كانت خدمة البريد مفعلة)
7. إنشاء المحفظة الإلكترونية (Wallet) تلقائياً

**API Endpoint:**
```
POST /api/auth/register
Body: { name, email, phone, password, role }
Response: { user, accessToken, refreshToken }
```

### 2.2 تسجيل الدخول (Login)
```
المستخدم → صفحة الدخول → إدخال البيانات → اختيار الدور → الدخول إلى لوحة التحكم
```

**الخطوات:**
1. إدخال البريد الإلكتروني وكلمة المرور
2. اختيار الدور النشط (إذا كان للمستخدم أدوار متعددة)
3. النظام يتحقق من البيانات ويولد JWT Token
4. توجيه المستخدم إلى لوحة التحكم حسب دوره

**API Endpoint:**
```
POST /api/auth/login
Body: { email, password, selectedRole }
Response: { user, accessToken, refreshToken }
```

### 2.3 تجديد الجلسة (Token Refresh)
```
انتهاء صلاحية Token → طلب تجديد تلقائي → Token جديد → استمرار الجلسة
```

**API Endpoint:**
```
POST /api/auth/refresh-token
Body: { refreshToken }
Response: { accessToken, refreshToken }
```

### 2.4 استعادة كلمة المرور
```
نسيت كلمة المرور → إدخال البريد → إرسال رابط إعادة التعيين → تعيين كلمة مرور جديدة
```

**API Endpoints:**
```
POST /api/auth/forgot-password → { email }
POST /api/auth/reset-password → { token, newPassword }
```

## 3. سير عمل مالك المشروع (Owner Workflow)

### 3.1 إنشاء مشروع جديد (Create Project)
```
لوحة التحكم → إنشاء مشروع → معالج 5 خطوات → نشر المشروع
```

**معالج إنشاء المشروع (5-Step Wizard):**

| الخطوة | الوصف | البيانات المطلوبة |
|--------|-------|-------------------|
| 1 | معلومات المشروع الأساسية | العنوان (عربي/إنجليزي)، النوع (فيلا/شقة/تجاري/سكني)، الوصف |
| 2 | تفاصيل المشروع | المساحة، الميزانية، الموقع، حالة التصاميم |
| 3 | مراحل البناء | اختيار المراحل وتوزيع النسب المئوية للميزانية |
| 4 | تحميل الملفات | المخططات، التصاميم، المستندات |
| 5 | المراجعة والنشر | مراجعة جميع البيانات والتأكيد |

**مراحل البناء الافتراضية:**
```
┌──────────────────────────────────────────────────┐
│ المرحلة          │ النسبة من الميزانية │ الوصف    │
├──────────────────────────────────────────────────┤
│ الأساسات         │ 25%                │ Foundation│
│ الهيكل الإنشائي  │ 30%                │ Structure │
│ الكهرباء         │ 15%                │ Electrical│
│ السباكة          │ 15%                │ Plumbing  │
│ التشطيبات        │ 15%                │ Finishing │
└──────────────────────────────────────────────────┘
```

**API Endpoint:**
```
POST /api/projects
Body: { title, titleEn, type, description, area, budget, location, stages[] }
Response: { project }
```

### 3.2 استقبال عروض الأسعار (Receive Quotations)
```
مشروع جديد → مقاولون يقدمون عروض → المالك يراجع → قبول/رفض العرض
```

**الخطوات:**
1. بعد نشر المشروع، يظهر للمقاولين في قائمة المشاريع المتاحة
2. المقاولون يقدمون عروض أسعار مع تفاصيل
3. المالك يتلقى إشعار بكل عرض جديد
4. المالك يراجع العروض ويقارن بينها
5. المالك يقبل عرض واحد → يتم تعيين المقاول للمشروع
6. العروض الأخرى ترفض تلقائياً

**API Endpoints:**
```
GET  /api/projects/:id/quotations    → قائمة العروض
PATCH /api/projects/quotations/:id   → قبول/رفض العرض
Body: { status: "accepted" | "rejected" }
```

### 3.3 تعيين مفتش (Assign Inspector)
```
المالك → تصفح المفتشين → اختيار مفتش → تعيينه للمشروع
```

**API Endpoints:**
```
GET /api/inspectors         → قائمة المفتشين مع التقييمات
GET /api/inspectors/:id     → ملف المفتش التفصيلي
```

### 3.4 متابعة سير المشروع (Track Project Progress)
```
لوحة التحكم → تفاصيل المشروع → متابعة المراحل → مراجعة البنود → الموافقة
```

**دورة الموافقة على البنود:**
```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  المقاول    │───▶│  المفتش     │───▶│  المالك     │───▶│  مكتمل      │
│  ينفذ العمل │    │  يفحص ويوافق│    │  يوافق نهائياً│   │  ✓          │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
       │                  │                  │
       ▼                  ▼                  ▼
   contractor_done   inspector_approved   owner_approved
```

### 3.5 إدارة المحفظة والمدفوعات (Wallet Management)
```
إيداع أموال → حجز مبلغ المشروع → دفع للمقاول عند إكمال المراحل
```

**API Endpoints:**
```
GET  /api/wallet          → رصيد المحفظة + سجل المعاملات
POST /api/wallet/deposit  → إيداع أموال
Body: { amount }
```

### 3.6 طلب تمويل بنكي (Bank Financing)
```
المالك → طلب تمويل → رفع المستندات → انتظار الموافقة
```

**API Endpoints:**
```
POST /api/financing/apply       → تقديم طلب تمويل
GET  /api/financing             → متابعة طلبات التمويل
POST /api/projects/bank-request → طلب تمويل بنكي مع مستندات
```

### 3.7 تقييم الأداء (Rating)
```
إكمال المشروع → تقييم المقاول → تقييم المفتش → نشر في معرض الإنجازات
```

**API Endpoint:**
```
POST /api/achievements/:projectId/rate
Body: { contractorRating, inspectorRating, comment }
```

## 4. سير عمل المقاول (Contractor Workflow)

### 4.1 تصفح المشاريع وتقديم العروض
```
لوحة التحكم → المشاريع المتاحة → تقديم عرض سعر → انتظار القبول
```

**الخطوات:**
1. المقاول يتصفح المشاريع الجديدة المتاحة
2. يراجع تفاصيل المشروع (النوع، المساحة، الميزانية، الموقع)
3. يقدم عرض سعر مع:
   - المبلغ الإجمالي
   - المدة المتوقعة
   - ملاحظات إضافية
4. ينتظر رد المالك (قبول/رفض)

**API Endpoint:**
```
POST /api/projects/:id/quotations
Body: { amount, duration, notes }
Response: { quotation }
```

### 4.2 تنفيذ المشروع (Execute Project)
```
قبول العرض → بدء العمل → تنفيذ المراحل → تسليم البنود
```

**دورة تنفيذ كل بند (Checklist Item):**
```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  1. المقاول يبدأ العمل على البند                            │
│     ↓                                                        │
│  2. المقاول يرفع صور وملفات التوثيق                         │
│     ↓                                                        │
│  3. المقاول يضيف ملاحظات                                    │
│     ↓                                                        │
│  4. المقاول يسلم البند (contractor_done)                     │
│     ↓                                                        │
│  5. إشعار للمفتش للمراجعة                                    │
│     ↓                                                        │
│  6. المفتش يوافق أو يرفض                                    │
│     ↓                                                        │
│  7. إذا رفض → المقاول يعيد العمل (العودة للخطوة 1)          │
│     إذا وافق → إشعار للمالك                                 │
│     ↓                                                        │
│  8. المالك يوافق نهائياً → البند مكتمل                      │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**API Endpoints:**
```
PATCH /api/projects/:itemId          → تحديث حالة البند
Body: { status: "contractor_done", notes, files[] }

POST /api/projects/:id/submit        → تسليم العمل
POST /api/items/:itemId/comments     → إضافة تعليق على البند
```

### 4.3 متابعة الأرباح (Track Earnings)
```
إكمال مرحلة → استلام الدفعة → مراجعة سجل الأرباح
```

**API Endpoints:**
```
GET /api/wallet              → رصيد المحفظة
GET /api/dashboard           → إحصائيات الأرباح والمشاريع
```

### 4.4 بناء السمعة (Build Reputation)
```
إكمال مشاريع ← تلقي تقييمات ← رفع المعدل ← جذب مشاريع أكثر
```

## 5. سير عمل المفتش (Inspector Workflow)

### 5.1 التقدم لفحص المشاريع
```
لوحة التحكم → المشاريع المتاحة → التقدم للفحص → تحديد الأتعاب
```

### 5.2 فحص ومراجعة العمل
```
إشعار بتسليم بند → مراجعة العمل → فحص الصور والملفات → الموافقة/الرفض
```

**دورة الفحص:**
```
┌────────────────────────────────────────────────┐
│                                                │
│  📋 استلام إشعار بتسليم بند                   │
│     ↓                                          │
│  🔍 مراجعة تفاصيل البند                       │
│     ↓                                          │
│  📸 فحص الصور والمستندات المرفقة              │
│     ↓                                          │
│  💬 إضافة ملاحظات الفحص                       │
│     ↓                                          │
│  ✅ الموافقة (inspector_approved)              │
│     أو                                         │
│  ❌ الرفض مع ذكر الأسباب                      │
│     ↓                                          │
│  📢 إشعار للمالك والمقاول                      │
│                                                │
└────────────────────────────────────────────────┘
```

**API Endpoints:**
```
POST /api/projects/:id/approve
Body: { itemId, status: "inspector_approved" | "rejected", notes }
```

### 5.3 متابعة الفحوصات
```
GET /api/dashboard → عدد الفحوصات المعلقة، المكتملة، النشطة
```

```
│  │    دفعة واحدة عند إكمال المرحلة في        │                │
│  │    جميع/أغلب الوحدات                       │                │
│  │                                            │                │

│  │    دفعات عند تحقيق نسب إنجاز محددة        │                │
```

```
│     │    لكل مرحلة بناء:                                  │           │
│     │      → المقاول ينفذ                                 │           │
│     │      → المشرف يتابع ويوثق الكميات                   │           │
│     │      → المفتش يفحص الجودة                           │           │
│     │      → المطور يراجع ويوافق                          │           │
│     │    إكمال المرحلة → صرف الدفعة                       │           │
│     │                                                      │           │
│     │  متابعة مستمرة:                                     │           │
│     │    → تحليل الفجوات                                  │           │
│     │    → مراقبة الكميات                                  │           │
│     │    → تتبع الجودة                                    │           │
│     │    → إدارة الدفعات                                  │           │
│     └──────────────────────────────────────────────────────┘           │
│     ↓                                                                   │
│  ④ اكتمال المجمع (completed)                                          │
│     جميع الوحدات مكتملة ومسلمة                                       │
│     ↓                                                                   │
│  ⑤ التقييم والتوثيق                                                   │
│     تقييم المقاول والمفتشين + أرشفة المشروع + نشر في معرض الإنجازات  │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 14. حالات المشروع (Project Status Flow)

```
new → awaiting_pricing → active → in_progress → completed
 │                                                  │
 └──── cancelled (يمكن الإلغاء في أي مرحلة) ────────┘
```

| الحالة | الوصف | الإجراء التالي |
|--------|-------|---------------|
| `new` | مشروع جديد تم إنشاؤه | انتظار عروض الأسعار |
| `awaiting_pricing` | بانتظار عروض المقاولين | المالك يقبل عرض |
| `active` | تم قبول العرض وتعيين الفريق | بدء التنفيذ |
| `in_progress` | جاري التنفيذ | إكمال جميع المراحل |
| `completed` | المشروع مكتمل | التقييم والنشر |
| `cancelled` | المشروع ملغي | - |

## 15. حالات بنود قائمة المهام (Checklist Item Status Flow)

```
pending → contractor_done → inspector_approved → owner_approved → completed
                │                   │
                ▼                   ▼
           rejected ◄──────── rejected
                │
                ▼
           pending (إعادة العمل)
```

| الحالة | الوصف |
|--------|-------|
| `pending` | البند بانتظار التنفيذ |
| `contractor_done` | المقاول أنهى العمل وسلّم |
| `inspector_approved` | المفتش فحص ووافق |
| `owner_approved` | المالك وافق نهائياً |
| `completed` | البند مكتمل بالكامل |
| `rejected` | مرفوض (يعود لـ pending) |
